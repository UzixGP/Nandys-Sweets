# Nandy's Sweets & Cakes — project guide

Catalog website for **Nandy's Sweets & Cakes**, Edisson's mom's home bakery in East Orange, NJ.
It is a **catalog, not a store**: customers browse and then contact the bakery over **WhatsApp** (primary)
or email. There is no checkout, no online payment, no backend and no database. Deployed on Vercel from
`github.com/UzixGP/Nandys-Sweets` (`main` auto-deploys). Edisson works from two machines (work laptop + home).

## Stack & conventions
- Next.js 16 App Router + TypeScript + Tailwind v4, fully static. `cacheComponents` is on:
  no `dynamicParams`; no `new Date()` during prerender (use `"use cache"` or compute in the browser).
- i18n without a library: routes under `src/app/[lang]/` (`es` default, `en`); `src/proxy.ts` redirects
  `/` and unprefixed paths to `/es`. All copy lives in `src/i18n/dictionaries/es.ts` (source of truth)
  and `en.ts` (typed against `es.ts`, so a missing key fails the build).
- Design tokens in `src/app/globals.css` (`bg-pink`, `bg-blue`, `bg-yellow`, `bg-cream`, `bg-blush`,
  `bg-lavender`, `text-cocoa`…). Fonts: Fredoka (`font-display`) + Nunito. Rounded cards, soft shadows,
  scalloped `<Scallop>` edges between alternating pastel sections. UI inspired by crumblcookies.com.
- Pages: home, `menu`, `gallery`, `custom-cakes` (inquiry form), `about`, `contact`.

## Security (audited 2026-10-16 — keep it this way)
- No secrets exist or are needed: no API keys, tokens, `.env`, backend, database or server actions. The
  repo is **public** — never commit credentials, street addresses or private customer data.
- Security headers + CSP live in `next.config.ts` (`poweredByHeader: false`). CSP is `'self'`-only; if a
  new third-party script/font/image host is ever added (analytics, maps…), extend the CSP for it and run
  `npm run qa` — it fails on any CSP violation.
- User input only flows into `wa.me` / `mailto:` links via `encodeURIComponent` (`src/lib/contact.ts`) and
  is rendered by React (auto-escaped). Don't add `dangerouslySetInnerHTML` with user data; the only one is
  the JSON-LD in `layout.tsx`, which escapes `<`.
- `scripts/build-gallery.mjs` strips EXIF/XMP (GPS, camera) from photos on every dev/build run, because
  photos are served publicly as-is. Run `npm run gallery` **before committing** new photos so the
  originals never enter git history.
- No `images.remotePatterns`: the image optimizer only serves local files (no SSRF).
